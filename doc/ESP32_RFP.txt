1. minishell
   prompt: RADER> 

   기능 : 
   네트워크 초기화(WiFi 또는 LAN8720) 후 실행된다.
   3초 동안 Key 입력이 없으면 main을 실행한다.

    명령어 : 

    1) printenv 
       env 내용과 DIP SW 모드를 보여준다. 
    2) test network 
       239.255.3.4 multicast 로 env 내용을 udp 8096 포트로 송출한다. 
       192.168.0.20:8096 unicast 로도 동시 송출.
    3) test led
       Phase 1: M_LED_1/2/3 동시 ON/OFF 3회 (500ms 간격, active-LOW)
       Phase 2: LED1 →2 →3 순서로 1초 간격 ON/OFF
    4) test dipsw
       DIP SW 현재 값 표시 (SW1=VN, SW0=VP, 0으로 읽힌 값 0~3)
    5) test i2c
       VL53L5CX I2C 주소(0x29, 0x52) 감지. SDA/SCL 교체 조합 및
       100kHz / 50kHz / 10kHz 3단계 속도로 순차 탐색.
    6) test lan8720
       LAN8720 PHY ID(MDIO) 확인 + 링크 + GW ping
    7) probe
       DIP SW 모드, 센서 종류 표시
    8) run
       Shell 종료 → main 실행
    9) reboot
       ESP32 재시작


2. IO Map 

2.1 TFmini Plus
   - 보드: TFmini Plus (Benewake)
   - 인터페이스: UART2 (115200 baud, 8N1)
   - 프레임: 9바이트, 100Hz
     [0x59][0x59][DistL][DistH][StrL][StrH][TempL][TempH][Checksum]
   - GPIO 배선:
     ESP32 GPIO16 (UART2 RX) ←→ TFmini Plus TX
     ESP32 GPIO17 (UART2 TX) ←→ TFmini Plus RX
   - 전원: 5V / GND
   - 감지 방식: 부팅 시 UART2 에서 500ms 동안 유효 프레임 수신 시도.
     수신 성공 시 TFmini 모드, 실패 시 VL53L5CX 모드로 자동 전환.

2.2 VL53L5CX
      message : 
      {"m":"cx","d":[11,16,17,15,479,474,725,788,12,16,17,16,398,446,460,845,14,13,17,15,14,414,458,909,13,15,12,17,13,15,289,467,9,12,15,20,20,14,116,15,14,14,15,16,16,17,335,378,12,14,16,16,17,21,19,740,14,17,16,16,17,18,18,692]}
      

   - 보드: Pololu VL53L5CX Time-of-Flight Sensor Carrier (irs18a PCB)
     제품번호: Pololu #3417
     (동일 PCB 로 VL53L7CX #3418 도 존재. 광학 개구부 형상으로 구분)
   - 인터페이스: I2C
   - I2C 주소: 0x29 (7-bit), 파워업 기본값
   - I2C 클럭: 50kHz (케이블 길이 ~30cm 고려, 레벨시프터 안정성)

   GPIO 배선:
     ESP32 GPIO5  ←→ 보드 SDA  (I2C Data)
     ESP32 GPIO4  ←→ 보드 SCL  (I2C Clock)
     ESP32 GPIO34 ←→ 보드 INT  (인터럽트, 현재 미사용 / 폴링 방식)
     보드 RST          N.C.    (보드 내부 GND 풀다운, 연결 불필요)
                               ※ RST 는 active-HIGH: HIGH 인가 시 I2C 리셋
                                  GND 고정(기본) = 정상 동작
     보드 LPN          3.3V 고정 (active-LOW disable, HIGH=정상동작)
                               ※ 보드 내부 VDD 풀업 있음. CPU 연결 불필요.

   전원 배선:
     ESP32 5V  (VIN) ←→ 보드 VIN  (레귤레이터 + 레벨시프터 전원)
     ESP32 3.3V      ←→ 보드 VDD  (I2C 레벨시프터 LOW측 기준전압)
                               ※ VDD 미연결 시 I2C 레벨시프터 동작 불가
                                  → NACK (err=2) 발생
     ESP32 GND       ←→ 보드 GND

   I2C 풀업:
     SDA, SCL 각각 2.2kΩ → 3.3V (외부 풀업, 30cm 배선 대응)

2.3 LED (active-LOW: LOW=ON, HIGH=OFF)
   IO13 : M_LED_1 (외부 LED 1)
   IO33 : M_LED_2 (외부 LED 2)
   IO14 : M_LED_3 (외부 LED 3, 빨간색) — 시스템 오류 표시
   - 부팅 3초 대기 중: M_LED_1 / M_LED_2 250ms 교대 점멸
   - Shell 진입 후: 3개 LED 모두 ON

   M_LED_3 (IO14) 오류 코드 표시 시나리오:
   코드  이름            조건                         LED3 동작
   ─────────────────────────────────────────────────────────────────
   0     ERR_NONE         정상                         상시 ON
   1     ERR_SENSOR_NONE  부팅 시 센서 미감지           1000ms 느린 점멸
   2     ERR_WIFI_LOST    WiFi 연결 끊김               200ms 빠른 점멸
   3     ERR_ETH_DOWN     LAN8720 링크 다운            200ms 빠른 점멸
   4     ERR_DHCP_FAIL    DHCP IP 할당 실패            200ms 빠른 점멸
   5     ERR_MQTT_FAIL    MQTT 브로커 연결 실패         200ms 빠른 점멸

   우선순위: WIFI_LOST > ETH_DOWN > DHCP_FAIL > MQTT_FAIL > SENSOR_NONE
   세부 원인은 shell 의 probe 명령어로 확인
   loop() 매 반복 실시간 평가 → LED3 즉시 반영 (millis 기반 비블로킹)

2.4 DIP Switch (Read-only)
   VP (GPIO36) : DIP_SW0 (LSB)
   VN (GPIO39) : DIP_SW1 (MSB)
   - 외부 10kΩ Pull-up, SW ON(닫힌) → GND = LOW(0)

   모드 테이블:
   SW1  SW0  값  모드          SSID    Broker
   ───────────────────────────────────────────────────────────────────
   0    0    0   WiFi           TRDR    192.168.0.203
   0    1    1   WiFi Dev       spdio   192.168.0.20
   1    0    2   Reserved       —       LAN8720 (→ 11과 동일)
   1    1    3   UTP / LAN8720  —       192.168.0.203
   전체 DHCP, MQTT Broker 포트: 1883, Topic: RDR

2.5 Status LED
   IO2  : 내장 LED (정상=점등, 오류=점멸)
          MQTT 연결 시 ON, 끊김 또는 재연결 중 OFF
          M_LED_3(빨간) 와 병행 사용 가능

2.6 센서 자동 선택
   - 부팅 시 UART2(GPIO16) 에서 TFmini 프레임 감지 (500ms)
   - 감지 성공: TFmini Plus 모드
   - 감지 실패: VL53L5CX 모드 (I2C)


3. main program

   ESP32 는 MQTT Publisher 이며, TOPIC 는 "RDR" 이다.

   3.1 센서 데이터 UDP 송출 (200ms 주기, 192.168.0.20:8096)

   TFmini Plus 포맷:
     {"dist":<cm>,"str":<strength>,"temp":<°C>}

   VL53L5CX 포맷:
     {"m":"cx","d":[d0,d1,...,d63]}
     (8x8=64 zones, 단위 mm, 좌상단→우하단 순서)

   3.2 Debug UDP 송출 (UDP 8096)

   디버그 목적으로 센서 데이터와 시스템 상태를 UDP 8096 포트로 추가 송출한다.

   3.2.1 송출 대상
     - Unicast  : 192.168.0.20:8096
     - Multicast: 239.255.3.4:8096 (동시 송출)

   3.2.2 송출 주기
     - 센서 데이터 : 200ms 주기 (3.1 과 동일 패킷 재사용)
     - 시스템 상태 : 1000ms 주기

   3.2.3 Debug 메시지 포맷

   센서 데이터 (기존 포맷 그대로):
     TFmini Plus : {"dist":<cm>,"str":<strength>,"temp":<°C>}
     VL53L5CX   : {"m":"cx","d":[d0,d1,...,d63]}

   시스템 상태:
     {"type":"dbg","uptime":<ms>,"sensor":"<tfmini|vl53>",
      "wifi":<rssi>,"ip":"<ip>","free_heap":<bytes>,"err":<code>}

     필드 설명:
       uptime    : 부팅 후 경과 ms (millis())
       sensor    : 현재 활성 센서 ("tfmini" 또는 "vl53")
       wifi      : WiFi RSSI (dBm), 미연결 시 0
       ip        : 현재 IP 문자열
       free_heap : ESP.getFreeHeap() 반환값 (bytes)
     err       : ErrorCode (0=정상, 1=센서미감지, 2=WiFi단절, 3=LAN링크다운, 4=DHCP실패, 5=MQTT실패)

   3.3 확정 사항
   1. DIP SW(IO36/IO39) 에 따라 TFmini Plus 또는 VL53L5CX 센서 값을 MQTT Publish 한다.
      WiFi 모드 (00/01) 및 LAN8720 모드 (10/11) 모두 192.168.0.203:1883 에 전송한다.

   2. M_LED_3 (IO14, 빨간) 로 오류 상태를 표시한다.
      ErrorCode 0~5 를 millis() 기반 비블로킹 점멸로 표현 (2.3 참고). 


4. LAN8720 연결

4.1 핀 매핑 (RMII 인터페이스)

   ESP32 DevKitC-V4    기능          LAN8720
   ──────────────────────────────────────────────────────
   IO19               TXD0          TXD0
   IO22               TXD1          TXD1
   IO21               TX_EN         TX_EN
   IO25               RXD0          RXD0/MODE0      ← 10K Pull-up
   IO26               RXD1          RXD1/MODE1      ← 10K Pull-up
   IO27               CRS_DV        CRS_DV/MODE2    ← 10K Pull-up
   IO18               MDIO          MDIO            ← 10K Pull-up
   IO23               MDC           MDC
   IO17               CLK (50MHz 출력)  XTAL1/CLKIN
   IO32               nRST            nRST (active-LOW)

   CLK 공급 방식 : ESP32 GPIO17 출력 (ETH_CLOCK_GPIO17_OUT)
                  → GPIO17 을 LAN8720 에 공급하므로 UART2 TX 미사용
                  → config.h: TFMINI_TX_PIN = -1

4.2 하드웨어 Pull-up / 부트스트랩

   RXD0 / RXD1 / CRS_DV 는 리셋 해제 시 MODE[2:0] 로 샘플링됨.
   세 핀 모두 10K Pull-up → MODE[2:0] = 111
   → LAN8720 All-Capable (10/100, Half/Full) + Auto-negotiation ON

   MDIO 10K Pull-up → 버스 idle 시 HIGH 유지 (IEEE 802.3 규격)

4.3 PHY 주소 (PHYAD0 / RXER 핀)

   PHYAD0 = GND  → PHY 주소 0  (기본값, config.h ETH_PHY_ADDR = 0)
   PHYAD0 = VCC  → PHY 주소 1
   ※ Reg18=0xC1C1 (PHYAD=1) 로 읽히지만 ETH.begin(addr=0) 으로 정상 동작 확인.
      MDIO bit-bang 과 EMAC 내부 MDIO 경로가 다르게 동작하는 것으로 추정.

4.4 nRST 처리 (GPIO32)

   GPIO32 → LAN8720 nRST (active-LOW)
   ETH.begin() 두 번째 인수(power 핀)에 GPIO32 를 전달하면
   Arduino-ESP32 ETH 라이브러리가 아래 순서를 자동으로 처리:

     1) GPIO32 LOW  → LAN8720 리셋 유지
     2) GPIO17 RMII 클럭(50MHz) 출력 시작
     3) GPIO32 HIGH → 클럭 안정 후 리셋 해제 + MODE 핀 샘플링
     4) MDIO 를 통한 PHY 초기화

   ※ nRST 를 RC 회로로만 처리하면 CLK 공급 전에 리셋이 해제될 수 있음
      → PHY 내부 state machine 초기화 불완전 → 링크 불안정 위험
      GPIO 제어 방식이 필수.
   ※ nRST 에 4.7µF 이상 캐패시터 금지: ETH.begin() 내부 LOW 펄스(~200µs)로
      충분히 방전 불가 → 리셋 미인식. 10kΩ 풀업만 사용.

4.5 GPIO17 충돌 해소

   기존 TFMINI_TX_PIN = 17 (UART2 TX) 이었으나,
   TFMini Plus 는 ESP32 수신 전용(단방향)이므로 TX 핀이 실제 불필요.
   Serial2.begin(..., RX_PIN, -1) 으로 TX 미할당 → GPIO17 해방.
   변경 후: TFMINI_TX_PIN = -1

4.6 RJ45 커넥터 — 품명, 배선, LED 연결

4.6.1 사용 부품

   품명  : RD1-125BAG1A
   제조사: Bothhand (보스핸드)
   타입  : 1×1 포트, 내장 트랜스포머(Integrated Magnetics) + 듀얼 LED
   패키지: Through-Hole, 8P8C (RJ45)
   규격  : 10/100Base-T 지원, IEEE 802.3 호환

4.6.2 센터탭 바이어스 저항 (필수)

   RD1-125BAG1A 는 내장 트랜스포머 센터탭 핀이 외부로 노출됨.
   49.9Ω (또는 47~51Ω, 정밀도 1%) 저항 → 3.3V 연결 필수.

   배선:
     TX 트랜스포머 센터탭 핀 → 49.9Ω → 3.3V
     RX 트랜스포머 센터탭 핀 → 49.9Ω → 3.3V

   미장착 시 공통 모드 전압 불안정 → TX 신호 왜형 → 스위치 미인식
   → DHCP 패킷 전송 실패 → 링크 불가.
   ※ 실측: 저항 미장착 시 링크가 10Mbps Half 로만 협상되고 DHCP 실패.
             저항 장착 후 100Mbps Full-Duplex 링크 및 DHCP 정상 동작 확인.

4.6.3 LED 배선

   RD1-125BAG1A 에는 LED 2개(Green / Yellow)가 내장되어 있으며,
   외부 제한 저항을 통해 LAN8720 LED 출력에 직접 연결.

   LAN8720 LED 핀 (24-QFN 기준):
     LED1 (pin 3  / REGOFF)   : Link / Activity  — Active-Low, push-pull
                                 링크 확립 시 ON, 트래픽 발생 시 점멸
     LED2 (pin 2  / nINTSEL)  : Speed            — push-pull
                                 HIGH = 10Mbps 또는 링크 없음 (no link)
                                 LOW  = 100Mbps
                                 ※ 100Mbps 운용 시 LED2=LOW → 소스 회로에서 LED OFF

   LAN8720A Strap (리셋 시 핀 샘플링):
     pin 3 (REGOFF)  : LOW 시 내부 1.2V 레귤레이터 OFF (외부 전원 사용 시)
                        HIGH(기본) 시 내부 레귤레이터 ON
     pin 2 (nINTSEL) : LOW 시 리셋 후 nINT 모드 (인터럽트 출력)
                        HIGH(기본) 시 리셋 후 LED2 모드 (Speed 표시)
     ※ LED2 Speed 표시 극성 변경을 위한 Strap 없음.
        소프트웨어 레지스터로도 LED2 극성 변경 불가.

   배선:
     LED1 (Active-Low → 싱크 방식):
       3.3V → 330Ω → RD1-125BAG1A Green  LED Anode (LEDG_A)
                      RD1-125BAG1A Green  LED Cathode (LEDG_K) → LAN8720 LED1 (pin 3)

     LED2 (소스 방식 — 현재 보드):
       LAN8720 LED2 (pin 2) → 240Ω → RD1-125BAG1A Yellow LED Anode (LEDY_A)
                                       RD1-125BAG1A Yellow LED Cathode (LEDY_K) → GND
       실제 동작: 부팅/No-link/10Mbps = LED ON, 100Mbps = LED OFF

     LED2 (싱크 방식 — 다음 보드 rev 권장):
       3.3V → 240Ω → RD1-125BAG1A Yellow LED Anode (LEDY_A)
                      RD1-125BAG1A Yellow LED Cathode (LEDY_K) → LAN8720 LED2 (pin 2)
       변경 후: 100Mbps = LED ON, 부팅/No-link/10Mbps = LED OFF

   ※ 실측 확인: LED1(Green) → 100Mbps 링크 시 ON, 트래픽 시 점멸 정상.
                LED2(Yellow) → 부팅/No-link 시 ON, 100Mbps 링크 확립 후 OFF (소스 회로 특성).

4.7 test lan8720 (Minishell 명령)

   실행 절차:
   1) ETH.begin (ETH_PHY_LAN8720, ETH_CLOCK_GPIO17_OUT)
      - GPIO32 로 nRST 시퀀스 자동 처리
   2) MDIO verify: PHY ID 확인 + 주요 레지스터 덤프
      - Addr 0: ID1=0x000F  ID2=0x81E3 → LAN8720 family OK (SMSC8720A)
   3) 링크 업 대기 (최대 5초)
      - 100Mbps Full-Duplex 확인
   4) DHCP IP 대기 (최대 8초)
      - PoE L2 스위치 사용 시 STP 수렴(~45초) 주의 → PortFast 활성화 권장
   5) GW (env.gw) 로 ICMP Ping x3
      - 실측: success=3/3, avg=0.6ms

  IO39  IN     DIP_SW1 (MSB)     DIP SW 스위치 1            입력전용(VN), 10kΩ Pull-up, SW ON→GND

5.4 LAN8720 — RJ45(RD1-125BAG1A) 특수 배선

  항목                 내용
  ─────────────────    ──────────────────────────────────────────────────────
  TX 센터탭 바이어스   TX 트랜스포머 센터탭 → 49.9Ω (1%) → 3.3V  (필수)
  RX 센터탭 바이어스   RX 트랜스포머 센터탭 → 49.9Ω (1%) → 3.3V  (필수)
  Link/Act LED         LAN8720 LED1 (pin 3/REGOFF,  Active-Low)  → 330Ω → 3.3V → RJ45 LED_K
  Speed LED            LAN8720 LED2 (pin 2/nINTSEL, 소스방식) → 240Ω → RJ45 LED_A → GND
                       실제: 부팅/No-link/10Mbps=ON, 100Mbps=OFF
                       Rev 수정: 싱크방식(3.3V→240Ω→LED→LED2)으로 변경 시 100Mbps=ON
  ※ 센터탭 저항 미장착 시: 10Mbps Half 로만 링크, DHCP 실패.
     장착 후 확인: 100Mbps Full-Duplex, DHCP 정상, Ping OK.

5.6 DIP SW 배선 (IO36/IO39)

  VP(IO36) = DIP_SW0 (LSB),  VN(IO39) = DIP_SW1 (MSB)
  입력전용 핀, 내부 Pull 없음 → 외부 10kΩ Pull-up 필수.

  배선:
    IO36 ──── 10kΩ ──── 3.3V     (Pull-up)
    DIP SW ON(닫힌) 시: IO36 ──── GND    (LOW = 0)
    (IO39 동일 구조)

  동작:
    SW ON(닫힌) : 0  /  SW OFF(열림) : 1
    모드 = (SW1 << 1) | SW0

  미연결 금지: 10kΩ Pull-up 미장착 시 플로팅 → 부팅마다 모드 불확정.


5.5 센서 자동 선택 로직 (부팅 시)

  부팅
   │
   ├─ UART2 (GPIO16) 에서 TFMini 프레임 감지 (500ms 대기)
   │       │
   │  감지 성공 ──→ TFMini Plus 모드
   │               GPIO16 = UART2 RX  (TFMini TX 수신)
   │               GPIO17 = LAN8720 CLK (UART2 TX 미사용)
   │
   └─  감지 실패 ──→ VL53L5CX 모드
                    Serial2.end()
                    GPIO16 = I2C_RST 출력으로 재사용
                    I2C: GPIO5(SDA) / GPIO4(SCL)
