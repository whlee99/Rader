

제안요청서 (Request for Proposal)
1. 프로젝트 개요 * 

1-1. 프로젝트 명: Srader - ToF 센서 융합 기반 무대 조명 안전 모니터링 시스템 개발 * 

1-2. 추진 배경 및 목적: * 무대 조명 장치는 설치 및 운영 중 정확한 각도를 유지하는 것이 중요하며,
특히 수직 이동(Tilting) 시 하부에 예상치 못한 장애물이 있을 경우 장비 파손 및 안전사고의 위험이 존재함.
* 본 프로젝트는 두 종류의 ToF(Time-of-Flight) 센서(TFmini Plus, VL53L5CX)를 ESP32에 연동하여,
조명 장치의 기울어짐 상태와 하부 장애물 유무를 실시간으로 감지하는 시스템을 개발하는 것을 목적으로 함.
* 본 시스템은 두 개의 통신 단계로 구성된다:
  - Acquisition 단계: 각 센서(S1 UART, S2 I2C)로부터 ESP32가 데이터를 수집하는 단계.
  - Telemetry 단계: ESP32가 수집·처리된 데이터를 WiFi/MQTT를 통해 RPi4로 전송하는 단계.
* RPi4는 MQTT Broker 역할을 수행하고 TOPIC은 "RDR"을 사용한다.
* 수집된 데이터는 PySide6 기반의 GUI 애플리케이션을 통해 로컬 LCD 화면에 직관적으로 표시하여,
현장 작업자가 즉각적으로 상태를 인지하고 대응할 수 있도록 함. * 
1-3. 기대 효과: * 조명 장치의 정밀한 설치 및 운영 지원 * 장비 이동 시 발생할 수 있는 충돌 사고 예방을 
통한 안전성 확보 * 실시간 모니터링을 통한 운영 효율성 증대

2. 제안 요청 사항 (상세 요구사항) *

2-0. 용어 정의

  * Acquisition (데이터 수집 단계)
    센서(S1, S2)로부터 ESP32(Edge)가 물리적 신호를 읽어들이는 단계.
    S1(TFmini Plus)은 UART, S2(VL53L5CX)는 I2C 프로토콜을 사용한다.

  * Telemetry (원격 전송 단계)
    ESP32가 수집·처리된 데이터를 WiFi 네트워크를 통해 MQTT 프로토콜로
    RPi4(MQTT Broker)에 전송하는 단계. TOPIC: "RDR"

2-0-1. Acquisition 통신 Payload (센서 제조사 정의 - 변경 불가)

  ┌─────────────────────────────────────────────────────────────────┐
  │ Type 1 : TFmini Plus (S1) - UART, 9600/115200 bps              │
  ├──────┬──────┬────────┬────────┬───────────┬───────────┬────────┤
  │ Byte │  0   │   1    │   2    │     3     │   4~7    │   8    │
  ├──────┼──────┼────────┼────────┼───────────┼───────────┼────────┤
  │ 값   │ 0x59 │  0x59  │ Dist_L │  Dist_H   │ (Strength │  Chk  │
  │      │(헤더)│ (헤더) │        │           │  , Temp)  │  Sum  │
  ├──────┼──────┴────────┴────────┴───────────┴───────────┴────────┤
  │ 설명 │ Dist = Dist_H<<8 | Dist_L  (단위: cm, 범위: 0~1200cm)  │

  └──────┴─────────────────────────────────────────────────────────┘

  │ signal_per_spad   │ Zone 별 신호 강도 (uint32)                  │
  │ nb_target_detected│ Zone 별 감지된 타겟 수 (uint8)              │
  ├───────────────────┼─────────────────────────────────────────────┤
  │ I2C Read 방식     │ 레지스터 폴링 또는 INT 핀 인터럽트 방식    │
  │ 복수 센서 구분    │ XSHUT 핀으로 순차 활성화 후 I2C 주소 재설정│
  └───────────────────┴─────────────────────────────────────────────┘

2-3. 소프트웨어 요구사항

    [ESP32 펌웨어] - Acquisition & Telemetry 담당
    * 개발 환경: PlatformIO (Arduino 프레임워크), C++
    * 핵심 개발 내용:
        1. [Acquisition] 센서 데이터 수집 모듈:
            * TFmini Plus (UART 통신)와 VL53L5CX 최대 10개 (I2C 통신) 센서로부터 데이터를 안정적으로 수집.
            * 두 종류의 센서를 동시에 사용하는 환경에서 데이터 충돌이나 지연이 발생하지 않도록 구현.
        2. [Telemetry] 데이터 수집 및 MQTT 송신:
            * 각 센서의 raw 데이터를 배열 순서(하드웨어 활성화 순서) 기준으로 그대로 전송.
            * 위치 의미 부여는 하지 않음. RPi4 UI에서 MAC 기반으로 결정.
            * payload에 ESP32 WiFi MAC 주소를 장치 식별자로 포함하여 송신.
            * 수집된 데이터를 WiFi를 통해 RPi4 MQTT Broker로 송신.
              (MQTT Broker: RPi4, TOPIC: "RDR")

    [RPi4 소프트웨어] - Telemetry 수신 및 GUI 표시 담당
    * 개발 환경: Raspberry Pi OS, Python 3.x
    * MQTT Broker: Mosquitto (TOPIC: "RDR")
    * 개발 대상 프로그램: PySide6 기반 2개
      ┌──────────────────┬──────────────────────┬────────────────────────┐
      │ 프로그램         │ 실행 플랫폼          │ 역할                   │
      ├──────────────────┼──────────────────────┼────────────────────────┤
      │ rader_monitor    │ RPi4 (Raspberry Pi OS│ Operation UI           │
      │ (PySide6)        │  로컬 LCD 전용)      │ 상시 실시간 모니터링   │
      ├──────────────────┼──────────────────────┼────────────────────────┤
      │ rader_setup      │ Windows/Linux PC     │ Setup(Provisioning) UI │
      │ (PySide6)        │ (현장 임시 접속)     │ 초기 설정·Calibration  │
      └──────────────────┴──────────────────────┴────────────────────────┘
    * Setup UI 방식: 현장 PC 네이티브 애플리케이션(rader_setup) + MQTT 직접 구독 + SSH config push
      ※ RPi4에 웹 서버·중계 로직 불필요. PC가 브로커에 직접 접속하여 센서 데이터 수신.
      ※ 현장 PC는 초기 설정 시에만 필요. 완료 후 분리 가능.
      [Setup 세션 절차]
        1. 현장 PC의 Setup 앱이 RPi4 MQTT Broker에 직접 접속하여 "RDR" 토픽 구독.
        2. ESP32가 송신하는 텔레메트리 패킷을 PC가 브로커를 통해 실시간 수신.
        3. PC Setup 앱에서 실시간 센서 데이터를 보며 전체 설정 완료.
        4. PC가 SSH(SCP)로 RPi4의 지정된 config 파일을 업데이트.
        5. RPi4가 config 리로드 후 정상 모드 복귀. 현장 PC 분리.
    * 핵심 개발 내용:
        1. [Telemetry] MQTT 수신 모듈:
            * ESP32로부터 TOPIC "RDR"로 수신된 센서 raw 데이터를 파싱하여 GUI에 전달.
        2. Calibration 모듈:
            * MAC 기반 센서 위치 매핑: RPi4 UI 설정 화면에서 ESP32의 MAC 주소별로
              배열 index와 물리 위치를 매핑하여 config 파일로 저장.
              (예: MAC AA:BB:CC:DD:EE:FF → s1[0]=Left(S1-L), s1[1]=Right(S1-R)
                   MAC AA:BB:CC:DD:EE:FF → s2[0]=위치A, s2[1]=위치B, ...)
              → IP 변경에 영향 없이 MAC으로 장치를 영구 식별.
              → ESP32 장치에는 MAC을 Serial 번호로 인쇄한 라벨을 부착하여
                 현장에서 Setup UI 입력 시 육안으로 확인 가능하도록 함.
            * 기울기 Calibration: 현장 설치 후 수평 기준 상태를 RPi4에서 측정·저장하여
              이후 측정값과의 차이로 실제 기울기 각도를 산출.
              (tilt_deg = atan((L - R) / sensor_gap) - baseline_offset)
            * 장애물 감지 Threshold Calibration: 현장 바닥 거리를 기준으로
              경보 발생 거리(threshold_mm) 및 기울기 허용 오차(tilt_limit_deg)를
              현장에서 설정·저장. 설정값은 로컬 파일(config)로 관리.
            * VL53L5CX 사용 수량 설정: 조명 Stand 크기에 따라 활성화할
              센서 수(1~10)를 GUI 설정 화면에서 지정.
        3. GUI 애플리케이션 개발:

            [Operation UI] - 현장 운영자용 실시간 모니터링 화면 (PySide6, RPi4 로컬 LCD)
                * 기울기 표시: 현재 장치의 기울기 상태를 시각적으로 표현 (예: 디지털 수평계, 각도 값 표시).
                  정상 범위를 벗어날 경우 색상(녹색→빨간색)으로 경고.
                * 장애물 맵: VL53L5CX의 8x8 데이터를 히트맵(Heatmap) 또는 그리드(Grid) 형태로 시각화하여
                  장애물의 위치와 거리를 직관적으로 표시.
                * 상태 알림: '정상', '기울기 경고', '장애물 감지' 등 시스템의 현재 상태를 텍스트로 명확하게 표시.
                * ESP32 연결 상태: MQTT 수신 여부로 ESP32 온라인/오프라인 상태 표시.

            [Setup UI] - 설치·설정 담당자용 초기 설정 화면 (현장 PC 네이티브 앱)
                * 동작 방식:
                  - PC Setup 앱이 RPi4 MQTT Broker에 직접 접속하여 "RDR" 토픽 구독.
                  - ESP32 텔레메트리 패킷을 PC가 실시간 수신 (RPi4 중계 불필요).
                  - PC 앱에서 실시간 센서 데이터를 확인하며 모든 설정 완료.
                  - SSH(SCP)로 RPi4의 지정된 config 파일 업데이트 후 세션 종료.
                  - RPi4에 별도 모니터/키보드 불필요. 설정 완료 후 PC 분리.
                * MAC 기반 센서 위치 매핑 설정:
                  MAC 주소는 ESP32가 MQTT payload에 자동 포함하여 전송하므로 별도 입력 불필요.
                  RPi4는 수신된 payload에서 MAC을 자동 감지하여 목록에 표시하며,
                  담당자는 표시된 MAC별로 s1[0]/s1[1] → L/R, s2[n] → 물리 위치 레이블만 지정.
                * VL53L5CX 활성 센서 수 설정: 현장 조명 Stand 크기에 따라 사용 수량(1~10) 지정.
                * 기울기 Calibration 실행: 현재 수평 기준 상태를 측정하여 baseline_offset 저장.
                * 장애물 감지 Threshold 설정: threshold_mm (장애물 경보 거리) 설정·저장.
                * 기울기 허용 오차 설정: tilt_limit_deg 설정·저장.
                * sensor_gap 설정: S1-L / S1-R 간 물리적 거리(cm) 입력.
                * 설정값은 로컬 config 파일로 저장·불러오기. 


3. 통신 규격의 정리

3-1. Acquisition (센서 → ESP32)
  구간   : 각 센서 → ESP32
  목적   : 물리 신호를 디지털 데이터로 수집
  특성   : 센서 제조사 정의 포맷 (변경 불가)

  3-1-1. TFmini Plus (S1-L, S1-R) - UART

    ┌──────┬──────┬────────┬────────┬─────────┬─────────┬────────┐
    │ Byte │  0   │   1    │   2    │    3    │  4~7    │   8    │
    ├──────┼──────┼────────┼────────┼─────────┼─────────┼────────┤
    │ 값   │ 0x59 │  0x59  │ Dist_L │  Dist_H │ Strength│  Chk  │
    │      │(헤더)│ (헤더) │ (Low)  │  (High) │  ,Temp  │  Sum  │
    └──────┴──────┴────────┴────────┴─────────┴─────────┴────────┘

    * 프레임 길이 : 9 Byte 고정
    * 통신 속도  : 115200 bps (기본값)
    * 거리 계산  : Dist[cm] = (Dist_H << 8) | Dist_L  (범위: 0 ~ 1200 cm)
    * 유효성 검사: Checksum = (Byte0 + ... + Byte7) & 0xFF == Byte8
    * 수신 주체  : ESP32 (UART0/UART1 각각 독립 포트, 배열 index 0/1로 전송)
                   ※ index의 L/R 위치 의미는 RPi4 Setup UI에서 MAC 기반 매핑으로 결정

  3-1-2. VL53L5CX (S2-1 ~ S2-n) - I2C

    ┌───────────────────┬────────────────────────────────────────────┐
    │ 필드              │ 설명                                       │
    ├───────────────────┼────────────────────────────────────────────┤
    │ distance_mm[64]   │ 8x8 Zone 별 거리값 (uint16, 단위: mm)     │
    │ target_status[64] │ Zone 별 측정 유효성 상태 코드 (uint8)     │
    │ signal_per_spad   │ Zone 별 신호 강도 (uint32)                 │
    │ nb_target_detected│ Zone 별 감지된 타겟 수 (uint8)             │
    └───────────────────┴────────────────────────────────────────────┘

    * 기본 I2C 주소 : 0x52
    * 복수 센서 구분: XSHUT 핀으로 순차 활성화 후 I2C 주소 개별 재설정
                     ※ 활성화 순서 = s2 배열 index (물리 위치 의미는 RPi4 Setup UI에서 MAC 기반 매핑으로 결정)
    * 읽기 방식     : INT 핀 인터럽트 또는 레지스터 폴링
    * 수신 주체     : ESP32 (I2C 버스 공유, XSHUT으로 주소 충돌 방지)


3-2. Telemetry (ESP32 → RPi4)
  구간   : ESP32 → RPi4 (WiFi, MQTT)
  목적   : 수집·처리된 센서 데이터를 원격 전송
  특성   : 본 프로젝트에서 정의하는 포맷 (설계 가능)

    * 프로토콜  : MQTT over WiFi (TCP)
    * Broker   : RPi4 (Mosquitto)
    * TOPIC    : "RDR"
    * QoS      : 1 (at least once)
    * 전송 형식 : JSON

  ※ 설계 원칙:
    - ESP32는 센서 raw 데이터를 배열 순서(하드웨어 활성화 순서) 기준으로 그대로 전송.
    - 장치 식별자로 WiFi MAC 주소를 사용. IP는 DHCP 자동 할당, 식별에 사용하지 않음.
    - MAC 주소는 ESP32 칩 제조 시 eFuse에 영구 기록되며, 펌웨어에서 자동으로 payload에 포함.
      RPi4는 수신 즉시 MAC을 자동 인식하므로 별도 입력 절차 없음.
    - 위치 의미(L/R, 물리 위치)는 RPi4 Setup UI에서 MAC 기반으로 매핑하여 결정.
    - 기울기 각도, 경보 threshold는 RPi4 현장 Calibration 값을 기준으로 산출.
    - VL53L5CX 활성 센서 수(1~10)는 현장 조건에 따라 RPi4 설정으로 관리.

    Payload 구조 (JSON):
    ┌─────────────────────────────────────────────────────────────┐
    │ {                                                           │
    │   "mac": "<ESP32_MAC>",         // ESP32 WiFi MAC (장치 Serial)│
    │   "ts" : <timestamp_ms>,        // 측정 시각 (Unix ms)    │
    │   "s1" : [<dist_cm>, <dist_cm>], // TFmini 거리값 배열(cm) │
    │                                 // index 0, 1 (배열 순서로 │
    │                                 //  위치 식별, Setup UI에서│
    │                                 //  MAC 기반 매핑)          │
    │   "s2" : [                      // VL53L5CX 데이터 배열   │
    │     {                           // (활성 센서만 포함, 최대 10개)│
    │                                 // 배열 index = 활성화 순서 │
    │       "d"  : [<uint16> x 64],   // 8x8 거리값 배열 (mm)   │
    │       "st" : [<uint8>  x 64],   // 8x8 유효성 status 배열 │
    │       "nb" : [<uint8>  x 64]    // 8x8 감지 타겟 수 배열  │
    │     }, ...                                                  │
    │   ]                                                         │
    │ }                                                           │
    └─────────────────────────────────────────────────────────────┘

    RPi4 처리 항목 (Payload 수신 후):
    ┌───────────────────┬────────────────────────────────────────────┐
    │ 처리 항목         │ 내용                                       │
    ├───────────────────┼────────────────────────────────────────────┤
    │ 위치 매핑         │ mac → s1[0]/s1[1]=L/R, s2[n]→물리위치 (Setup UI 설정값)│
    │ 기울기 각도 산출  │ atan((L-R)/sensor_gap) - baseline_offset   │
    │ 기울기 경보 판단  │ abs(tilt_deg) > tilt_limit_deg (Calib값)  │
    │ 장애물 경보 판단  │ d[i] < threshold_mm (Calib값) 인 Zone 존재 │
    │ 활성 센서 수 관리 │ 설정 파일(config)에서 사용 수량 로드       │
    └───────────────────┴────────────────────────────────────────────┘


3-3. Provisioning (Setup PC → RPi4)
  구간   : Setup PC → RPi4
  목적   : 현장 초기 설정값을 RPi4에 등록
  특성   : 본 프로젝트에서 정의하는 포맷 (설계 가능)
  시점   : 초기 설치 시 1회 또는 현장 조건 변경 시

  3-3-1. Provisioning 세션 절차

    ┌──────┬──────────────────────────────────────────────────────────┐
    │ 단계 │ 내용                                                     │
    ├──────┼──────────────────────────────────────────────────────────┤
    │  1   │ Setup PC 앱이 RPi4 MQTT Broker에 접속, "RDR" 토픽 구독  │
    │  2   │ ESP32 Telemetry 패킷 실시간 수신 (3-2 payload 동일)      │
    │  3   │ PC 앱에서 MAC 확인, 위치 매핑 및 전체 Calibration 완료  │
    │  4   │ PC 앱이 SSH(SCP)로 RPi4 config 파일 push                │
    │  5   │ RPi4 config 리로드 → 정상 운영 모드 복귀                │
    └──────┴──────────────────────────────────────────────────────────┘

  3-3-2. Provisioning Config 파일 (SSH push 대상)

    * 전송 방식 : SSH(SCP)
    * 파일 경로 : RPi4 내 지정 경로 (예: /etc/rader/config.json)
    * 파일 형식 : JSON

    Config 파일 구조:
    ┌─────────────────────────────────────────────────────────────┐
    │ {                                                           │
    │   "devices": [                                             │
    │     {                                                       │
    │       "mac"          : "<ESP32_MAC>",  // 장치 식별자      │
    │       "s1"           : ["L", "R"],     // s1[0], s1[1]     │
    │                                        //  물리 위치 레이블│
    │       "s2"           : ["위치A", ...], // s2[n] 위치 레이블│
    │       "active_s2"    : <int>           // 활성 VL53 수(1~10)│
    │     }, ...                             // 복수 장치 지원   │
    │   ],                                                        │
    │   "sensor_gap_cm"    : <float>,        // S1-L/R 간 거리   │
    │   "baseline_offset"  : <float>,        // 수평 기준 보정값 │
    │   "tilt_limit_deg"   : <float>,        // 기울기 경보 한계 │
    │   "threshold_mm"     : <int>           // 장애물 경보 거리 │
    │ }                                                           │
    └─────────────────────────────────────────────────────────────┘

    * RPi4는 config 파일 변경 감지(inotify 등) 또는 재시작으로 설정값 반영.


4. 네트워크 구성도

  네트워크 환경 (확정)
  ┌────────────────┬──────────────────────────┐
  │ 장치           │ IP 주소                  │
  ├────────────────┼──────────────────────────┤
  │ WiFi AP (GW)   │ 192.168.0.1   (고정)     │
  │ RPi4           │ 192.168.0.203 (고정)     │
  │ ESP32 (전체)   │ DHCP 자동 할당           │
  │ Setup PC       │ DHCP 자동 할당 (임시)    │
  └────────────────┴──────────────────────────┘
  * RPi4는 시스템 내 유일 1대.
  * ESP32 펌웨어의 MQTT Broker 주소 = 192.168.0.203 (변경 불필요).


4-1. 운용 모드 (Operation Mode)
  * 상시 동작 상태. ESP32 → RPi4 Telemetry 수신 → LCD 표시.
  * Setup PC 不在. WiFi AP, RPi4, ESP32만 네트워크에 존재.

  [WiFi AP / Router]  192.168.0.1
         |
         |  (WiFi)
         +-------------------------------+
         |                               |
  +------+--------+               +------+-----------+
  | ESP32 (n대)   |               | RPi4             |
  | IP : DHCP     |               | IP : 192.168.0.203 (고정)
  | MAC: 장치 식별|  MQTT "RDR"   |                  |
  | Telemetry  ---|-------------->| Mosquitto (Broker)|
  | 송신          |               |   port: 1883     |
  +---------------+               |                  |
         :                        | PySide6          |
  (복수 장치 동시 운용 가능)       | Operation UI     |
                                  | (LCD)            |
                                  +------------------+

  * ESP32 IP는 DHCP 자동 할당. 장치 식별은 MAC 사용.
  * ESP32 펌웨어 내 Broker 주소 192.168.0.203은 고정 기재. 변경 불필요.


4-2. 셋업 모드 (Provisioning Mode)
  * 초기 설치 또는 설정 변경 시에만 사용. Setup PC를 네트워크에 임시 연결.
  * Setup PC는 두 가지 독립 통신을 동시에 사용:
    - MQTT 구독 ("RDR", 192.168.0.203:1883) : 실시간 센서 데이터 수신
    - SSH / SCP  (192.168.0.203)             : config 파일 push

  [WiFi AP / Router]  192.168.0.1
         |
         |  (WiFi)
         +---------------------+---------------------+
         |                     |                     |
  +------+--------+     +------+-----------+   +-----+----------+
  | ESP32 (n대)   |     | RPi4             |   | Setup PC       |
  | IP : DHCP     |     | IP: 192.168.0.203|   | IP : DHCP (임시)|
  |               | MQTT|                  |MQTT "RDR"          |
  | Telemetry  ---+---->| Mosquitto    <---+----구독(수신)      |
  | 송신          |"RDR"| (Broker)         |   |                |
  +---------------+     |                  |SSH| Setup App      |
                        | config 파일  <---+SCP| (Provisioning) |
                        | 갱신·리로드      |   | config push    |
                        |                  |   +----------------+
                        | PySide6          |
                        | Operation UI     |
                        | (LCD)            |
                        +------------------+

  * Mosquitto 다중 구독 지원. RPi4와 Setup PC가 동시에 "RDR" 구독해도 간섭 없음.
  * Setup PC의 MQTT/SSH 접속 대상: 192.168.0.203 고정.
  * 설정 완료 후 Setup PC 분리 → 운용 모드로 자동 전환.
